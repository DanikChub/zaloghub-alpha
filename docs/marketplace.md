# Маркетплейс ZalogHub Alpha

## Что перенесено и где проходит граница

Один API NestJS + Prisma/PostgreSQL. `MarketplaceOffer` — публикация; `Deal`, договоры, платежи, расчёты и журнал финансов остаются отдельными сущностями. Старый Express/Sequelize не используется. Из старого проекта выборочно адаптированы шесть regex-обработчиков каналов и поведение Telegram-сборщика: серверный список источников, фото, группировка альбомов и загрузка истории. Прямого соединения сборщика с PostgreSQL нет.

Следующий этап — явное создание досье из выбранного предложения с сохранением ссылки на исходную публикацию, правами доступа и подтверждением параметров. Проверки, ИИ, документы, договоры и взыскание в этом этапе не реализованы. Кнопки запуска проверки нет.

## Требования и подготовка

Node.js 24+, pnpm, PostgreSQL. Из корня: `pnpm install`. Примеры конфигурации не содержат секретов; действующие `.env` не перезаписывать.

API использует существующие `DATABASE_URL`, `JWT_SECRET`, настройки почты и авторизации Alpha. Дополнительно задать `MARKETPLACE_COLLECTOR_TOKEN`: случайный секрет не короче 32 символов. При отсутствии/коротком секрете служебные маршруты закрыты. Пример: `apps/api/.env.marketplace.example`. Добавить значения в локальный `apps/api/.env`.

Сборщик: скопировать `apps/collector/.env.example` в `apps/collector/.env`, задать:

- `MARKETPLACE_API_URL` — корень API, локально `http://localhost:3000`, удалённо только HTTPS.
- `MARKETPLACE_COLLECTOR_TOKEN` — тот же секрет.
- `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` — собственные Telegram API-реквизиты и ранее авторизованная GramJS StringSession. Интерактивная авторизация автоматически не запускается.
- `COLLECTOR_STORAGE` — каталог очереди (относительно apps/collector), по умолчанию `.local/collector`.
- Необязательные `TG_PROXY_HOST`, `TG_PROXY_PORT`, `TG_PROXY_USERNAME`, `TG_PROXY_PASSWORD` — SOCKS5.

Сессии, `.env`, `.local`, storage игнорируются Git. Очередь содержит оригиналы публикаций и фотографии: ограничить доступ к диску и сохранять её при перезапусках. Не запускать несколько процессов на одном каталоге очереди.

## Миграция — только после проверки целевой БД

Миграция `20261108000000_marketplace` добавляет четыре таблицы, индексы и внешние ключи, не удаляет данные и не меняет финансовые таблицы. Перед применением проверить `DATABASE_URL`, резервную копию и наличие предыдущих миграций Alpha. В этом задании рабочая БД не мигрировалась.

Из `apps/api`:

```powershell
pnpm db:validate
pnpm db:generate
# Только после отдельного согласования целевой БД:
pnpm db:migrate
```

## Источники

`apps/api/marketplace-sources.example.json` содержит шесть поддерживаемых ключей и фиктивные отключённые каналы. Заменить channelId на реальный Telegram channel ID (`-100…`), по возможности задать channelUsername без @, контакт `https://t.me/...`, title и enabled. Не использовать демонстрационные ID в сборе. Список источников хранится в основном API, обновляется сборщиком каждые 30 секунд. Изменение конфигурации переподписывает обработчики.

Из `apps/api`:

```powershell
# Проверка JSON без соединения с БД:
node scripts/marketplace-sources.mjs marketplace-sources.example.json
# После проверки целевой БД, для своего локального файла:
node --env-file=.env scripts/marketplace-sources.mjs marketplace-sources.local.json --apply
```

Повторная запись по key обновляет источник. Изменять channelId у источника с публикациями не следует: для другого канала нужен отдельный источник. Публичного маршрута управления источниками нет; настройку выполняет оператор с доступом к БД. Неизвестный обработчик сохраняет сообщение со статусом ERROR.

## Запуск

Из корня в отдельных терминалах:

```powershell
pnpm dev:api
pnpm dev:web
# Только при согласованном живом подключении Telegram:
pnpm dev:collector
```

Веб: `http://localhost:5173/marketplace`, требуется вход. В `apps/web/.env` задать `VITE_API_URL=http://localhost:3000` для прямого локального API; существующий `/api` предполагает reverse proxy. API разрешает CORS для localhost:5173.

Загрузка истории — только вручную, ограниченно, из `apps/collector`:

```powershell
# sourceId — UUID из GET /internal/marketplace/sources, не channelId.
# Не выполнять массово без отдельного согласования:
pnpm run history <sourceId> 2026-11-01 100
# Повторить только сохранённую очередь, без Telegram-соединения:
pnpm retry
```

Лимит — 1..10000 сообщений одного источника; альбомы у границы догружаются соседними ID. Сначала проверьте маленький диапазон. Повторная история безопасна по идентичности публикаций. Фото с ошибкой загрузки требуют повторения истории; текст уже сохранён. При падении процесса до записи события на диск восстановление тоже выполняется историей; автоматический catch-up Telegram пропусков не реализован.

## Доставка, расчёты и происхождение

Ключ публикации — sourceId + externalMessageId, для альбома дополнительно sourceId + albumId. Совпадение адресов никогда не объединяет источники. Транзакция и PostgreSQL advisory lock сериализуют конкурентные доставки одного источника. Запоздалая версия не заменяет более новую; отметки хранятся отдельно по userId + offerId и не меняются импортом.

Исходные текст, ID сообщений, даты публикации/редактирования/получения, ссылка и фото сохраняются. Текст записывается сборщиком на диск до скачивания фото; очередь удаляется только после успешного ответа API, повторяется через 30 секунд и после перезапуска. Ошибки API/разбора не уничтожают исходник. Ошибки 4xx остаются в очереди до исправления конфигурации. Повтор всех неотправленных элементов может создать нагрузку при длительном сбое; для большого потока потребуется backoff и мониторинг очереди.

`declared` хранит извлечённые заявления, `calculated` — результаты формул, `inferred` — город/тип объекта/контакт источника и основание предположения. Денежные вычисления используют Decimal. Ставка без явного периода и интервальная ставка остаются неизвестными. Явные 3% годовых не превращаются в 3% месячных; годовая ставка делится на 12. Подстановка 4% отсутствует. LTV требует суммы и положительной стоимости залога; предполагаемый доход требует суммы и известной ставки, доход за срок — ещё и срока. Модель дохода — простые проценты, без комиссий и возврата тела. Стоимость из публикации не является независимой оценкой. Балл привлекательности/надёжности не переносится.

Неоднозначные/изменившиеся форматы каналов могут дать частичные данные: исходник всегда доступен в карточке. Подтверждение значений оператором и геокодирование — будущие улучшения. Фото хранятся в PostgreSQL (до 10 файлов по 5 МБ на доставку), выдаются через JWT-защищённый API; для большого объёма рекомендуется отдельное объектное хранилище с авторизованной выдачей.

## API

JWT: `GET /marketplace/dictionaries`, `GET /marketplace/offers`, `GET /marketplace/offers/:id`, `PATCH /marketplace/offers/:id/mark` (`saved`/`hidden`: boolean), `GET /marketplace/photos/:id`.

Фильтры: search, city, objectType, borrowerType, sourceId, view=all|saved|hidden; min/max Amount, Value, Rate, Term, Ltv (например minAmount). sort=publishedAt|loanAmount|collateralValue|interestRateMonthly|loanTermMonths|ltv; order=asc|desc; page (от 1), limit (1..60). Неизвестные числовые параметры не попадают в диапазоны; в сортировке NULL идут последними. Скрытые исключаются из обычной/сохранённой ленты только для текущего пользователя.

Служебные, `x-collector-token`: `GET /internal/marketplace/sources`, `POST /internal/marketplace/messages` (multipart: raw JSON, photos[] с именами `<messageId>.jpg/png/webp`). Структура raw: sourceId, externalMessageId, albumId?, messageIds[], text, publishedAt, revisionAt (ISO). Ошибка разбора объявления — успешный приём со статусом ERROR/PARTIAL; ошибка формата транспорта — 400. Файлы проверяются по сигнатуре, имена не используются как пути.

## Импорт сохранённых заявок старого ZalogHub

`apps/api/scripts/import-legacy-marketplace.mjs` импортирует экспорт `sources`/`deals` в **локальную** Alpha. По умолчанию только проверяет данные. Требует предварительную сборку API. Для записи добавляется `--apply`; перед ней автоматически создаётся pg_dump целевой БД в игнорируемом `.local/legacy-import`. Путь к pg_dump можно задать через `PG_DUMP_PATH`. Миграции скрипт не выполняет.

Из `apps/api`:

```powershell
node --env-file=.env scripts/import-legacy-marketplace.mjs ../../.local/legacy-import/export.json ../../.local/legacy-import/photos/deals
# Запись после проверки вывода:
node --env-file=.env scripts/import-legacy-marketplace.mjs ../../.local/legacy-import/export.json ../../.local/legacy-import/photos/deals --apply
```

Источники сопоставляются по ключу с проверкой Telegram channel ID; существующие предложения — по sourceId + externalMessageId. Уже существующие предложения и пользовательские отметки не перезаписываются. Вложения повторно не добавляются по содержимому и стабильному имени старого файла. Неиспользуемые файлы старого storage не создают лишних вложений.

Параметры заново извлекаются из исходного текста, без старой подставленной ставки и балла привлекательности. Исходные поля старого парсера сохраняются для сверки в declared.legacyImport; оригинальные даты и ссылки сохраняются. Старая БД не хранит albumId и Telegram ID каждого фото: они не выдумываются, для старых фото используется ключ legacy:<filename>. При будущей загрузке Telegram-истории альбом, чей исходный ID публикации отличается от сохранённого старым сборщиком, может потребовать отдельной сверки; импорт одного и того же экспорта идемпотентен.

При фактическом переносе 08.11.2026 обнаружены два видео, ошибочно сохранённых старым сборщиком с расширением JPG. Импорт определяет тип по содержимому, сохраняет video/mp4 / video/quicktime и интерфейс предлагает воспроизведение. QuickTime может не поддерживаться конкретным браузером. Лимит старого вложения при прямом импорте — 50 МБ; ограничение нового Telegram-приёма фото не меняется.

## Диагностика подключения Telegram

Из apps/collector: `pnpm diagnose` проверяет TCP до SOCKS5-прокси и SOCKS5-туннель до Telegram:443. Команда не выполняет MTProto-авторизацию и не читает сообщения. Значения сессии, пароли и адрес прокси не выводятся. Успех туннеля ещё не подтверждает обмен MTProto или действительность сессии.

Прокси управляется TG_PROXY_ENABLED=true/false. Если флаг не задан, наличие TG_PROXY_HOST включает прокси для совместимости. TG_PROXY_TYPE=socks5 (по умолчанию) либо mtproto; для MTProto нужен TG_PROXY_SECRET обычного 16-байтного формата или dd, как в старом сборщике. Fake-TLS не поддерживается этой версией GramJS. Диагностическая команда предназначена для SOCKS5.

При обычном запуске выводятся этапы TCP-транспорта, первого ответа протокола и подписки на каналы. Принудительный TCP-порт 443 сохранён. Ложный результат GramJS connect проверяется до проверки сессии. Таймаут подключения 45 секунд; сетевые ошибки показываются без исходных сообщений, которые могут содержать реквизиты.
